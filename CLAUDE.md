# Python Under the Hood: interactive course site

A free, static, interactive Python course: lesson notes, editable code cells that run real Python
in the browser, quizzes and auto-graded exercises. It mirrors the 4-part / 47-section structure of Dr. Fred Baptiste's *Python 3: Deep Dive* (Udemy):
324 lectures from the course, plus 5 extra refresher lessons (Part 1 · Section 02: strings, lists, tuples,
sets, dictionaries). Lesson text is original.

## Commands

```bash
npm run dev                      # dev server, http://localhost:4321
npm run build                    # static build -> dist/  (SITE_BASE=/repo/ for GitHub Pages)
npm run test:content             # run every lesson cell + exercise in Pyodide (slow: ~10 min)
npm run test:content -- --show part-2/section-04   # one section, printing each cell's output
npm run test:content -- --quiz part-2/section-04   # also run quiz code snippets
npm run curriculum               # regenerate src/data/curriculum.json from ../python-deepdive
```

## Layout

- `src/data/curriculum.json` is generated by `scripts/build_curriculum.py` from the source repo
  `../python-deepdive` (one lecture per notebook or lecture folder). Don't edit it by hand. Use the
  script's `ORDER_OVERRIDES` (unnumbered notebooks), `NOT_LECTURES` and `EXTRA_LECTURES` (lectures that
  exist only as captions, inserted in course order).
- Content collections (`src/content.config.ts`):
  - `src/content/lessons/part-N/section-NN/<slug>.md`: one per lecture (frontmatter `title`, `summary`,
    `minutes`, optional `files`, `packages`)
  - `src/content/sections/part-N/section-NN.md`: section overview
  - `src/content/practice/part-N/section-NN.yaml`: `quiz` + `exercises` (+ optional `files`, `packages`)
- Pages: `src/pages/index.astro`, `about.astro`, `[part]/index.astro`, `[part]/[section]/index.astro`,
  `[part]/[section]/[lecture].astro`, `[part]/[section]/practice.astro`. All links go through `url()` in
  `src/lib/course.ts` so a non-root `base` works.
- Interactive runtime:
  - `public/py-worker.js` is a Web Worker that loads Pyodide 0.29.3 (CPython 3.13) from jsDelivr. It
    contains the Python `HARNESS` string, which the content checker also extracts and runs, so the browser
    and the tests always agree. Change the harness in one place only.
  - `src/scripts/runner.ts` is the main-thread client: lazy start, 15 s timeout, auto-restart on timeout
    or fatal Pyodide crash (deep C-level recursion), and loading the page's data `files`/`packages` before
    the first cell runs.
  - `src/scripts/pycell.ts` defines `<py-cell>`, which is produced from ```` ```python run ```` fences by
    `src/lib/remark-pycell.mjs`. Cells share one namespace per page (a real `__main__` module); running a
    cell first runs earlier unrun cells; `fresh` cells get their own namespace.
  - `src/scripts/practice.ts` runs quizzes and exercises (tests run in a fresh namespace; drafts are kept
    in localStorage). `progress.ts` holds per-visitor progress in localStorage, always wrapped in try/catch.
- Data files for lessons live in `public/data/part-N/section-NN/` and are written into Pyodide's working
  directory at the path listed in `files:`.

## Rules for content (full guide: `docs/AUTHORING.md`)

- Write in original words. Captions (`../python-deepdive/Part 1/Captioning`) are for learning the material
  only; never quote or publish them. Don't mention the instructor, Udemy, "the course" or "the video" in
  lesson text. Credit appears only on the home and About pages (the user's explicit choice), with a
  GPL-3.0 License link in the footer.
- Every claim about output must be verified in Pyodide (`--show`). Show Python 3.13 behavior and add
  `<div class="callout modern">` notes where it differs from older notebooks.
- Every `run` cell must finish without an uncaught exception, in about 2 s or less. Quote YAML strings that
  contain `: `.
- The "Python Updates" sections of Parts 2–4 reuse Part 1 · Section 10 lessons 01–04 (the source
  notebooks are identical). Keep them in sync if you edit the originals.

## Verifying a change

1. `npm run test:content` (or the affected section) ends with `All content checks passed`.
2. `npm run build` completes with no errors or warnings.
3. Browser end-to-end tests (Playwright) were run from a scratch directory outside this repo. To re-create
   them, see "Browser tests" in `docs/ROADMAP.md`.

## Known limits

- PyPI-only packages (marshmallow, serpy) can't load in Pyodide, so those lessons use static snippets
  verified locally. `zoneinfo` has no tz data in Pyodide.
- Deep recursion through C code (`lru_cache`, recursive `__getattr__`) overflows the browser stack. The
  runner reports it and restarts Python, and lessons avoid running such code.
- Pyodide is 32-bit WebAssembly: `sys.getsizeof`, hash widths and addresses differ from 64-bit CPython.
